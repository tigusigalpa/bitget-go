# Bitget Go SDK v1.2.0

This release adds the official UTA deep candle-history route and immutable HTTP
response evidence for historical market consumers. Recent candles, recent public
fills, funding history and injected HTTP transports retain their existing APIs.

## Added

- `Market.GetHistoryCandles` calls `/api/v3/market/history-candles` with category,
  symbol, interval, type, startTime, endTime and limit selectors. Requests support
  at most 100 candles, independently of recent `GetCandles`' 1,000-candle route.
  Exact numeric strings, provider ordering and extra early candles from documented
  end-time rounding are preserved.
- `GetHistoryCandlesWithReceipt` and `GetLiquidationsWithReceipt` return immutable
  `models.RESTReceipt` evidence: exact bounded response-body bytes, HTTP status,
  local receipt time before decoding and allowlisted request metadata without
  credentials/headers/host. Accessors copy mutable values. Receipts retain at
  most 10 MiB; oversize/interrupted bodies fail with an incomplete receipt, and
  HTTP/API/decoding errors retain the response whenever one was received.
- `Market.GetLiquidations` returns `models.PartialLiquidations` with exact amount,
  price and event-time strings and opaque cursor pagination. These are delayed
  observations from the last three days, not a complete liquidation history:
  stable event identity, amount units and REST aggregation are not guaranteed
  by the audited contract. No synthetic identity or unit conversion is added.
- A public history example, source-linked synthetic fixtures, contract audit and
  boundary/error/cancellation/pagination/immutability regression tests.

## Coverage boundaries

The UTA market catalog documents only recent public fills. Private
`/api/v3/trade/fills` is account history, and Classic v2 public history uses a
different API. This release does not substitute either for an undocumented UTA
public historical fills route.

History time selectors are forwarded unchanged. The provider does not explicitly
guarantee equality at the start/end boundaries; the SDK preserves inclusive and
exclusive responses and does not infer complete coverage from page size. A full
receipt means complete HTTP bytes, not complete market history.

## Upgrade and validation

```bash
go get github.com/tigusigalpa/bitget-go@v1.2.0
```

Go 1.21 remains supported. Normal/race tests, vet, build and module verification
passed on Go 1.21 in Linux; Windows normal/race and module checks also passed.
`golangci-lint v2.14.0` reports no issues. All fixtures are classified synthetic
inputs, not live exchange captures; live boundary behaviour is not asserted.
